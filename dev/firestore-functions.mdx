## School & User Management

### `checkUserHasSchool(uid)`

ตรวจสอบว่า user สังกัดโรงเรียนไหน อ่านจาก `userScheduler/{uid}` แล้วตรวจ `setupComplete` จาก profile

```typescript
async function checkUserHasSchool(
  uid: string
): Promise<SchoolCheckResult | null>
```

**Return:** `{ schoolId, setupComplete }` หรือ `null` ถ้าไม่พบ

### `createSchoolForNewUser(firebaseUser)`

สร้าง school ใหม่สำหรับ user ที่เพิ่งสมัคร ใช้ `writeBatch` เขียน 2 documents:
- `{schoolId}/profile` -- `setupComplete: false`, `ownerUid`
- `userScheduler/{uid}` -- `role: "OWNER"`, `schoolId`

```typescript
async function createSchoolForNewUser(
  firebaseUser: User
): Promise<SchoolCheckResult>
```

### `loadSchoolDocument(schoolId)`

โหลดข้อมูลโรงเรียนทั้ง 3 sub-docs พร้อมกัน (profile, subscription, address)

```typescript
async function loadSchoolDocument(
  schoolId: string
): Promise<SchoolDocument | null>
```

### `loadUserScheduler(uid)`

โหลดข้อมูล member จาก `userScheduler/{uid}`

```typescript
async function loadUserScheduler(
  uid: string
): Promise<UserSchedulerData | null>
```

## Subscription & Setup

### `saveSubscription(schoolId, packageCode)`

บันทึก subscription (Step 1 ของ setup wizard) ตั้ง trial 30 วันอัตโนมัติ

```typescript
async function saveSubscription(
  schoolId: string,
  packageCode: string  // "1" = small, "2" = large, "3" = AI
): Promise<void>
```

### `uploadSchoolLogo(schoolId, file)`

อัพโหลด logo ไป Firebase Storage ที่ path `schools/{schoolId}/logo.png`

```typescript
async function uploadSchoolLogo(
  schoolId: string,
  file: File
): Promise<string>  // download URL
```

### `saveSchoolProfile(schoolId, profile)`

บันทึก school profile (Step 2) ใช้ `{ merge: true }`

```typescript
async function saveSchoolProfile(
  schoolId: string,
  profile: SchoolProfileData
): Promise<void>
```

### `saveSchoolAddress(schoolId, addressData)`

บันทึกที่อยู่โรงเรียน (Step 3)

```typescript
async function saveSchoolAddress(
  schoolId: string,
  addressData: SchoolAddressData
): Promise<void>
```

### `saveContactAndComplete(schoolId, uid, memberUpdate, schoolContact)`

บันทึก contact info และ mark `setupComplete = true` (Step 4 -- final step) ใช้ `writeBatch` เขียน 2 docs:
- profile -- เพิ่ม contact + setupComplete = true
- userScheduler/{uid} -- update member info

```typescript
async function saveContactAndComplete(
  schoolId: string,
  uid: string,
  memberUpdate: { fullName, position, email, phone },
  schoolContact: SchoolContactData
): Promise<void>
```

## Schedule Timeslot CRUD

### Standard Mode (3-collection atomic)

<Callout type="info">
  Standard mode เขียน/ลบ ทั้ง 3 collections (teachers, students, rooms) พร้อมกันผ่าน `runTransaction` เพื่อป้องกัน data inconsistency
</Callout>

| Function | คำอธิบาย |
|---|---|
| `saveScheduleTimeslot(schoolId, fileId, entry)` | บันทึก timeslot -- ตรวจ conflict ก่อนใน transaction |
| `deleteScheduleTimeslot(schoolId, fileId, entry)` | ลบ timeslot ทั้ง 3 collections |
| `moveScheduleTimeslot(schoolId, fileId, entry, newDay, newPeriod)` | ย้าย timeslot -- ตรวจ conflict ปลายทาง |
| `toggleTimeslotPin(schoolId, fileId, entry, pinValue)` | toggle pin ทั้ง 3 collections |

**Conflict detection:** `saveScheduleTimeslot` ใช้ `runTransaction` อ่านทั้ง 3 docs ก่อน ถ้า exists จะ throw:
- `"CONFLICT_TEACHER"` -- ผู้สอนมีคาบอยู่แล้ว
- `"CONFLICT_STUDENT"` -- ผู้เรียนมีคาบอยู่แล้ว
- `"CONFLICT_ROOM"` -- ห้องถูกใช้แล้ว

### Partial Mode (1-collection only)

สำหรับ advanced scheduling ที่เขียนแค่ 1 collection:

| Function | คำอธิบาย |
|---|---|
| `saveScheduleTimeslotPartial(...)` | บันทึก timeslot ใน 1 collection |
| `deleteScheduleTimeslotPartial(...)` | ลบ timeslot จาก 1 collection |
| `moveScheduleTimeslotPartial(...)` | ย้าย timeslot ภายใน 1 collection |
| `checkTimeslotConflictsBatch(...)` | ตรวจ conflict หลาย entity พร้อมกัน |

### Wizard Mode (atomic multi-entity)

สำหรับ wizard mode ที่จัดคาบให้หลาย entity พร้อมกัน:

| Function | คำอธิบาย |
|---|---|
| `saveWizardTimeslotAtomic(...)` | บันทึก timeslot ให้ทุก entity ใน 1 transaction |
| `deleteWizardTimeslotAtomic(...)` | ลบ timeslot ของทุก entity |
| `deleteWizardTimeslotsBulkAtomic(...)` | ลบหลาย slots -- แบ่ง chunk <= 500 (Firestore limit) |

### Schedule Settings

| Function | คำอธิบาย |
|---|---|
| `saveScheduleSettings(schoolId, fileId, data)` | บันทึก card field settings + hideOnOwnView |
| `loadScheduleSettings(schoolId, fileId)` | โหลด schedule display settings |

### Entity Timeslots

| Function | คำอธิบาย |
|---|---|
| `loadEntityTimeslots(schoolId, fileId, entityType, entityId)` | โหลด timeslot ทั้งหมดของ entity 1 ตัว |

## Internal Helper Functions

ฟังก์ชันภายในที่ไม่ได้ export แต่สำคัญ:

### `stripUndefined(obj)`

ลบ key ที่มี value เป็น `undefined` ออก เนื่องจาก Firestore ไม่รับ undefined

```typescript
function stripUndefined(obj: object): Record<string, unknown> {
  return Object.fromEntries(
    Object.entries(obj).filter(([, v]) => v !== undefined)
  );
}
```
