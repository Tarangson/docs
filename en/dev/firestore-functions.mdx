## School & User Management

### `checkUserHasSchool(uid)`

Checks which school a user belongs to. Reads from `userScheduler/{uid}` and checks `setupComplete` from the profile.

```typescript
async function checkUserHasSchool(
  uid: string
): Promise<SchoolCheckResult | null>
```

**Returns:** `{ schoolId, setupComplete }` or `null` if not found.

### `createSchoolForNewUser(firebaseUser)`

Creates a new school for a newly registered user. Uses `writeBatch` to write 2 documents:
- `{schoolId}/profile` -- `setupComplete: false`, `ownerUid`
- `userScheduler/{uid}` -- `role: "OWNER"`, `schoolId`

```typescript
async function createSchoolForNewUser(
  firebaseUser: User
): Promise<SchoolCheckResult>
```

### `loadSchoolDocument(schoolId)`

Loads all 3 school sub-docs at once (profile, subscription, address).

```typescript
async function loadSchoolDocument(
  schoolId: string
): Promise<SchoolDocument | null>
```

### `loadUserScheduler(uid)`

Loads member data from `userScheduler/{uid}`.

```typescript
async function loadUserScheduler(
  uid: string
): Promise<UserSchedulerData | null>
```

## Subscription & Setup

### `saveSubscription(schoolId, packageCode)`

Saves the subscription (Step 1 of the setup wizard). Automatically sets a 30-day trial.

```typescript
async function saveSubscription(
  schoolId: string,
  packageCode: string  // "1" = small, "2" = large, "3" = AI
): Promise<void>
```

### `uploadSchoolLogo(schoolId, file)`

Uploads a logo to Firebase Storage at the path `schools/{schoolId}/logo.png`.

```typescript
async function uploadSchoolLogo(
  schoolId: string,
  file: File
): Promise<string>  // download URL
```

### `saveSchoolProfile(schoolId, profile)`

Saves the school profile (Step 2). Uses `{ merge: true }`.

```typescript
async function saveSchoolProfile(
  schoolId: string,
  profile: SchoolProfileData
): Promise<void>
```

### `saveSchoolAddress(schoolId, addressData)`

Saves the school address (Step 3).

```typescript
async function saveSchoolAddress(
  schoolId: string,
  addressData: SchoolAddressData
): Promise<void>
```

### `saveContactAndComplete(schoolId, uid, memberUpdate, schoolContact)`

Saves contact info and marks `setupComplete = true` (Step 4 -- final step). Uses `writeBatch` to write 2 docs:
- profile -- adds contact + setupComplete = true
- userScheduler/{uid} -- updates member info

```typescript
async function saveContactAndComplete(
  schoolId: string,
  uid: string,
  memberUpdate: { fullName, position, email, phone },
  schoolContact: SchoolContactData
): Promise<void>
```

## Schedule Timeslot CRUD

### Standard Mode (3-collection atomic)

<Callout type="info">
  Standard mode writes/deletes across all 3 collections (teachers, students, rooms) simultaneously via `runTransaction` to prevent data inconsistency.
</Callout>

| Function | Description |
|---|---|
| `saveScheduleTimeslot(schoolId, fileId, entry)` | Save a timeslot -- checks for conflicts within the transaction |
| `deleteScheduleTimeslot(schoolId, fileId, entry)` | Delete a timeslot from all 3 collections |
| `moveScheduleTimeslot(schoolId, fileId, entry, newDay, newPeriod)` | Move a timeslot -- checks for conflicts at the destination |
| `toggleTimeslotPin(schoolId, fileId, entry, pinValue)` | Toggle pin across all 3 collections |

**Conflict detection:** `saveScheduleTimeslot` uses `runTransaction` to read all 3 docs first. If any exist, it throws:
- `"CONFLICT_TEACHER"` -- the teacher already has a period scheduled
- `"CONFLICT_STUDENT"` -- the student already has a period scheduled
- `"CONFLICT_ROOM"` -- the room is already in use

### Partial Mode (1-collection only)

For advanced scheduling that writes to only 1 collection:

| Function | Description |
|---|---|
| `saveScheduleTimeslotPartial(...)` | Save a timeslot in 1 collection |
| `deleteScheduleTimeslotPartial(...)` | Delete a timeslot from 1 collection |
| `moveScheduleTimeslotPartial(...)` | Move a timeslot within 1 collection |
| `checkTimeslotConflictsBatch(...)` | Check conflicts for multiple entities at once |

### Wizard Mode (atomic multi-entity)

For wizard mode that schedules multiple entities at once:

| Function | Description |
|---|---|
| `saveWizardTimeslotAtomic(...)` | Save a timeslot for all entities in 1 transaction |
| `deleteWizardTimeslotAtomic(...)` | Delete a timeslot for all entities |
| `deleteWizardTimeslotsBulkAtomic(...)` | Delete multiple slots -- chunks to <= 500 (Firestore limit) |

### Schedule Settings

| Function | Description |
|---|---|
| `saveScheduleSettings(schoolId, fileId, data)` | Save card field settings + hideOnOwnView |
| `loadScheduleSettings(schoolId, fileId)` | Load schedule display settings |

### Entity Timeslots

## Internal Helper Functions

Internal functions that are not exported but are important:

### `stripUndefined(obj)`

Removes keys with `undefined` values, since Firestore does not accept undefined.

```typescript
function stripUndefined(obj: object): Record<string, unknown> {
  return Object.fromEntries(
    Object.entries(obj).filter(([, v]) => v !== undefined)
  );
}
```
