## Getting Started with Contributing

<Steps>
  <Step title="Fork & Clone">
    ```bash
    git clone https://github.com/your-org/tarangson-webapp.git
    cd tarangson-webapp
    npm install
    ```
  </Step>

  <Step title="Create a branch">
    ```bash
    git checkout -b feature/your-feature-name
    ```

    See the [Branch Naming Convention](#branch-naming) below.
  </Step>

  <Step title="Develop and test">
    ```bash
    npm run dev    # Start dev server
    npm run lint   # Check code
    npm run build  # Test build
    ```
  </Step>

  <Step title="Commit and Push">
    ```bash
    git add .
    git commit -m "feat: เพิ่มฟีเจอร์ใหม่ (add new feature)"
    git push origin feature/your-feature-name
    ```
  </Step>

  <Step title="Create a Pull Request">
    Open a PR to the `main` branch with a detailed description of your changes.
  </Step>
</Steps>

## Code Style Guide

### TypeScript

- Use **TypeScript** exclusively -- no `.js` files
- Use **strict mode** (tsconfig)
- Define types explicitly -- avoid `any`
- Use `interface` for object shapes and `type` for unions/intersections

```typescript
// Good
interface Teacher {
  id: string;
  code: string;
  firstName: string;
}

// Good
type DayOfWeek = "MON" | "TUE" | "WED" | "THU" | "FRI" | "SAT" | "SUN";

// Avoid
const data: any = {};
```

### React Patterns

- Use the **`"use client"`** directive for client components
- Use **functional components** only (no class components)
- Use `memo()` for frequently re-rendered components

```typescript
"use client";

import { useState, useCallback, memo } from "react";

const MyComponent = memo(function MyComponent({ data }: Props) {
  const [state, setState] = useState<string>("");
  // ...
});
```

### State Management

- Use **React Context** for global state (`AuthContext`)
- Use **`useState`** + **`useCallback`** + **`useMemo`** for local state
- Do not use Redux, Zustand, or any external state management library

### Styling

- Use **Tailwind CSS** only -- no CSS modules or styled-components
- Use the **`cn()`** utility (clsx + tailwind-merge) for conditional classes
- Use **shadcn/ui** components when an appropriate component is available

```typescript
import { cn } from "@/lib/utils";

<div className={cn(
  "px-4 py-2 rounded-lg",
  isActive && "bg-primary text-primary-foreground",
  isDisabled && "opacity-50 cursor-not-allowed"
)} />
```

### File Organization

- **1 page = 1 file** in the `app/` folder, following the Next.js App Router convention
- **Shared utilities** go in `app/lib/`
- **UI components** (shadcn/ui) go in `components/ui/`
- **Custom components** go in `app/components/`

### Naming Conventions

| Type | Convention | Example |
|---|---|---|
| Files (pages) | lowercase kebab-case (directory) | `app/timetable/page.tsx` |
| Components | PascalCase | `ProtectedRoute`, `FileSelectDialog` |
| Functions | camelCase | `loadTeachers`, `saveScheduleTimeslot` |
| Types/Interfaces | PascalCase | `Teacher`, `ScheduleEntry` |
| Constants | UPPER_SNAKE_CASE | `DEFAULT_ACADEMIC`, `DAY_LABELS` |
| CSS classes | Tailwind utilities | `"flex items-center gap-2"` |

## Branch Naming {#branch-naming}

```
{type}/{short-description}
```

| Type | When to Use |
|---|---|
| `feature/` | Adding a new feature |
| `fix/` | Fixing a bug |
| `refactor/` | Restructuring code |
| `docs/` | Updating documentation |
| `chore/` | Maintenance tasks (dependencies, config) |

Examples:
```
feature/wizard-template-editor
fix/conflict-detection-race-condition
refactor/extract-schedule-utils
```

## Commit Message Format

Use **Conventional Commits** format:

```
{type}: {description}
```

| Type | Description |
|---|---|
| `feat` | New feature |
| `fix` | Bug fix |
| `refactor` | Code restructuring |
| `docs` | Documentation update |
| `chore` | Maintenance tasks |
| `style` | Formatting changes, no logic impact |

Examples:
```
feat: เพิ่มปุ่ม card/print mode toggle ในหน้าแสดงตาราง (add card/print mode toggle button to timetable view)
fix: dropdown เปลี่ยนมุมมองใช้ไฟล์เดิม ไม่ต้องเลือกแฟ้มใหม่ (fix view-switch dropdown to reuse current file)
fix: card text สีดำทั้งหมด -- เอาสีน้ำเงินออกใน print mode (make all card text black -- remove blue in print mode)
```

<Callout type="info">
  Commit messages can be written in Thai -- just make sure to start with the type prefix in English.
</Callout>

## Development Tips

### Firestore Named Database

The app uses a named database `"tarangson"`, not the default:

```typescript
db = getFirestore(app, "tarangson");
```

You must create the named database in the Firebase Console before developing.

### Null Safety

Firebase variables (`auth`, `db`, `storage`) can be `null` if no API key is available:

```typescript
// Every function must check for null
if (!db) throw new Error("Firestore ยังไม่พร้อมใช้งาน");
if (!db) return null;  // For read functions
if (!db) return [];    // For list functions
```

### Batch Write Limit

Firestore `writeBatch` supports a maximum of **500 operations** per batch -- you must chunk if exceeded:

```typescript
const CHUNK = 500;
for (let i = 0; i < allRefs.length; i += CHUNK) {
  const chunk = allRefs.slice(i, i + CHUNK);
  const batch = writeBatch(db);
  // ...
  await batch.commit();
}
```

### stripUndefined Helper

Firestore does not accept `undefined` values -- use `stripUndefined()` before writing:

```typescript
await setDoc(ref, stripUndefined(data));
```
